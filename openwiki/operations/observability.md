# Operations: Observability

The observability stack is structured logging via `log/slog`, Prometheus metrics via `/metrics`, and a typed error vocabulary (`error_codes.go`) that the transport layer maps to HTTP envelopes. Admin-side surfaces (`/admin/system-health`, `/admin/cron-health`) consume these signals.

## Structured logging

`backend/internal/infra/observability/` provides the slog wrapper. Conventions:

- Use `slog` everywhere; never `fmt.Printf`.
- Log at critical junctions (transaction begin/commit, provider calls, worker retries).
- Do not log at debug level in production builds.
- Carry the request id and actor id when relevant.

`observability.GetLogger()` is the entry point. Handlers receive a logger via DI; services receive one via their constructor.

## Metrics

- Prometheus metrics are exposed at `/metrics` and scraped by the host.
- `api_metrics.go` middleware counts per-endpoint requests, latencies, and status codes.
- DB metrics are exposed via `internal/infra/observability/db_metrics.go` (connection pool, slow queries).
- Worker metrics come from asynq's built-in inspector and a custom wrapper that tracks per-task counts, retries, and terminal failures.

## Error codes and request id

- `internal/domain/error_codes.go` — standardized error codes (`ERROR_CODE_*` constants). Every typed domain error returns one of these.
- `internal/domain/errors.go` — typed error constructors (`NewNotFoundError`, `NewValidationError`, `NewConflictError`, …).
- `internal/transport/http/response/error_translator.go` — the only place that maps domain errors to HTTP status codes and Vietnamese user-facing messages. Handlers must use the helper.
- Request id is generated by middleware (`api_metrics.go` or a dedicated request-id middleware) and propagated through `context.Context`, headers (`X-Request-Id`), and the structured log fields. The frontend echoes the same header via the Axios client for correlation.

## Admin UI surfaces

- `frontend/src/components/system-health/` — DB pool stats, request rates, error rates. Polled via TanStack Query.
- `frontend/src/components/cron-health/` — per-cron-task status (last run, next scheduled, last error). Reads from a dedicated admin endpoint.
- `frontend/src/components/admin/system-health` and `cron-health` (the page-level entry points) mount these widgets with Vietnamese labels.

## What's logged where

- **HTTP requests** — middleware logs the request line, the actor id, the duration, and the status code.
- **Domain events** — publish-after-commit; the event bus emits a small audit line on the consumer side.
- **Workers** — log the task type, the input ids, the outcome, and any retry decision.
- **Provider calls** — log the wire state, the invoice number, and the response time. Sensitive payloads are not logged.
