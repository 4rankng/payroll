# Phase 2: Timesheet Exporter (Chuyển OnePay)

## Overview

Add an "Chuyển OnePay" dropdown item to `/admin/timesheet`. Clicking it (with cycle/project/period filters applied) generates a "Yêu cầu chuyển tiền" `.xlsx` in OnePay-API-compatible `eMB_BulkPayment` format, with a **SWIFT code column** pre-resolved from each employee's bank record. Each row gets a fresh VFIC transaction code. Admin downloads the file and later uploads it to `/admin/wallet` (Phase 3+).

**Standalone shippable**: this phase delivers value on its own — admins can immediately use the exported file with the existing manual OnePay workflow, even before the wallet-side pipeline (Phase 3+) ships.

## Requirements

- **Functional**: Generate `eMB_BulkPayment`-format `.xlsx` from selected approved timesheets. 7 columns: STT, Account No, Beneficiary, Beneficiary Bank (Vietnamese), **Mã SWIFT** (NEW), Amount, Payment Detail (with VFIC). Reuse existing `ExportPlanner.Plan()` + `TransactionCode` infrastructure.
- **Non-functional**: Generation ≤2s for typical 50-row exports. Employees missing bank info are skipped (not failed) with a warning list in the response. Admin-only authorization.

## Architecture

### Reuse strategy

The existing 9Pay export at `POST /payrolls/export-bulk-transfer` already:
- Plans the transfer set via `ExportPlanner.Plan(req)` → returns `ExportPlan` with `EmployeeProjectAmounts` map + `TransactionCodes`.
- Generates VFIC codes via `transactionCodeRepo.CreateBatch`.
- Produces an `eMB_BulkPayment` Excel via `excel.Service.fillMBankTransferData`.

The new exporter reuses ALL of that and adds:
1. **SWIFT resolution**: for each row, look up `employee.bank.bank_code` → `BankRepository.FindByBankCode(bank_code).SwiftCode`.
2. **New column G "Mã SWIFT"**: added to the eMB output.
3. **New endpoint**: `POST /api/v1/payrolls/export-onepay-bulk` (separate from the existing 9Pay `export-bulk-transfer` so the two flows don't collide).

### Service: `OnePayExporter`

New file `backend/internal/app/services/payroll/bulktransfer/onepay_exporter.go`:

```go
type OnePayExporter struct {
    planner             *ExportPlanner
    excelService        *excel.Service
    bankRepo            domain.BankRepository
    employeeRepo        EmployeeRepository
    transactionCodeRepo TransactionCodeRepository
    fileRepo            BulkTransferFileRepository
    eventBus            domain.EventBus
    clock               clock.Clock
    logger              *slog.Logger
}

type OnePayExportResult struct {
    ExcelBytes       []byte   `json:"-"`
    Filename         string   `json:"filename"`
    TotalCount       int      `json:"total_count"`
    TransferAmount   int64    `json:"transfer_amount"`
    SkippedEmployees []SkippedEmployee `json:"skipped_employees"` // missing bank info
}

type SkippedEmployee struct {
    EmployeeID   uint   `json:"employee_id"`
    EmployeeName string `json:"employee_name"`
    Reason       string `json:"reason"` // "missing_bank_info", "unresolved_swift"
}

func (e *OnePayExporter) Export(ctx context.Context, req *dto.ExportBulkTransferRequest) (*OnePayExportResult, error)
```

### Export flow

```
POST /api/v1/payrolls/export-onepay-bulk  (Admin only)
  ├─ 1. Validate request (cycle/project/period filters)
  ├─ 2. plan := e.planner.Plan(ctx, req)  ← REUSE existing ExportPlanner
  │     Returns ExportPlan{EmployeeProjectAmounts, TransactionCodes, ...}
  ├─ 3. For each (employeeProjectKey, amount) in plan:
  │     a. employee := employeeRepo.GetByID(employeeID)
  │     b. if employee.BankID == nil OR employee.BankAccountNumber == "":
  │        skip; append to skippedEmployees with reason="missing_bank_info"
  │        continue
  │     c. bank := bankRepo.GetByID(*employee.BankID)  (or via preload)
  │     d. if bank.SwiftCode == "":
  │        skip; append to skippedEmployees with reason="unresolved_swift"
  │        continue
  │     e. vfic := plan.TransactionCodes[key]  ← VFIC already generated by planner
  │     f. row := OnePayExportRow{
  │          OrderNo:       i+1,
  │          AccountNo:     employee.BankAccountNumber,
  │          AccountName:   employee.BankAccountName,
  │          Bank:          bank.BranchName,         // Vietnamese display name
  │          SwiftCode:     bank.SwiftCode,          // e.g. "MBBEVNVX"
  │          Amount:        amount,
  │          PaymentDetail: vfic,                    // contains VFIC code
  │          VFICCode:      vfic,
  │       }
  ├─ 4. Persist VFIC codes via transactionCodeRepo.CreateBatch  ← REUSE existing pattern
  ├─ 5. Generate Excel via excelService.GenerateOnePayExport(rows)  ← NEW method
  │     Uses eMB_BulkPayment layout with 7 columns (incl. Mã SWIFT)
  ├─ 6. Persist BulkTransferFile record for audit (Validation Decision V2):
  │     - filename, total_count, transfer_amount, source='onepay_export'
  │     - asset_id (store the .xlsx via fileStorage)
  │     - data JSON with VFIC → timesheet_ids mapping (for later entity_id resolution)
  ├─ 7. Publish WalletBulkTransferFileExportedEvent
  └─ 8. Return OnePayExportResult{ExcelBytes, Filename, counts, skipped, ExportID}
```

### Excel output format

Sheet `eMB_BulkPayment`, header row 2, data row 3+:

| Col | Header (Vietnamese) | English alias |
|-----|---------------------|---------------|
| A | `STT\n(Ord. No.)` | `Ord. No.` |
| B | `Số tài khoản\n(Account No.)` | `Account No.` |
| C | `Tên người thụ hưởng\n(Beneficiary)` | `Beneficiary` |
| D | `Ngân hàng thụ hưởng/Chi nhánh\n(Beneficiary Bank)` | `Beneficiary Bank` |
| **E** | **`Mã SWIFT\n(SWIFT Code)`** | **`SWIFT Code`** |
| F | `Số tiền\n(Amount)` | `Amount` |
| G | `Nội dung chuyển khoản\n(Payment Detail)` | `Payment Detail` |

Note: This shifts Amount/PaymentDetail to columns F/G (vs the user's original attached file which had them at E/F). The parser in Phase 1 uses header-name mapping (not fixed offsets), so it handles this correctly. The exported file becomes the canonical input format for the wallet-page upload.

### Endpoint

```go
// In routes_disbursement.go, alongside existing export-bulk-transfer:
payrolls.POST("/export-onepay-bulk", container.Handlers.Payroll.ExportOnePayBulk)
```

Returns the Excel as a blob with metadata in custom `X-` headers (Validation Decision V1):

```
Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet
Content-Disposition: attachment; filename="Yeu_cau_chuyen_tien_<cycle>_<YYYYMMDD_HHMMSS>.xlsx"
X-Total-Count: 3
X-Transfer-Amount: 3964500
X-Skipped-Count: 1
X-Export-Id: 42   ← BulkTransferFile.id (Validation Decision V2)
```

Frontend reads headers to show toast + skipped-employees dialog (Phase 5).

### Handler

```go
// In payroll.go, alongside ExportBulkTransfer:
func (h *PayrollHandler) ExportOnePayBulk(c *gin.Context) {
    var req dto.ExportBulkTransferRequest
    if err := c.ShouldBindJSON(&req); err != nil { /* 400 */ }

    userID := getUserIDFromContext(c)
    result, err := h.onePayExporter.Export(c.Request.Context(), &req)
    if err != nil { /* 500 */ }

    // Option A: direct blob download with metadata in headers
    c.Header("Content-Disposition", fmt.Sprintf(`attachment; filename="%s"`, result.Filename))
    c.Header("X-Total-Count", strconv.Itoa(result.TotalCount))
    c.Header("X-Transfer-Amount", strconv.FormatInt(result.TransferAmount, 10))
    c.Header("X-Skipped-Count", strconv.Itoa(len(result.SkippedEmployees)))
    c.Data(200, "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet", result.ExcelBytes)
}
```

1. **Define types** in `onepay_exporter.go`: `OnePayExporter`, `OnePayExportResult`, `SkippedEmployee`, `OnePayExportRow`.

2. **Write `OnePayExporter.Export`** per the 8-step flow above. Reuse `planner.Plan()` for the heavy lifting; the new code is the SWIFT resolution loop + skip-list accumulation.

3. **Add `excel.Service.GenerateOnePayExport`**:

   - Add column E header `Mã SWIFT\n(SWIFT Code)` (shifts original E/F to F/G).

   - Return bytes via `f.WriteToBuffer()`.

4. **Write the handler** `ExportOnePayBulk` per pseudocode above.

5. **Wire bootstrap**: in `container.go`, instantiate `OnePayExporter` with `bankRepo`, `employeeRepo`, `planner`, etc. Add to `PayrollHandler` deps.

6. **Register route** in `routes_disbursement.go`.

   - VFIC generation: each row has a unique VFIC code; persisted via `transactionCodeRepo.CreateBatch`.
   - Excel format: parse output with `excelize.OpenReader`, assert 7 columns with correct headers (incl. `Mã SWIFT`), assert SWIFT values match `bank.SwiftCode`.

## Risk Assessment

- **Risk**: Employee bank_code doesn't exist in banks table → `FindByBankCode` returns nil. **Mitigation**: skip employee with reason `unresolved_swift`; surface in warning list. Admin fixes employee record and re-exports.
- **Risk**: Two concurrent exports of overlapping timesheets → duplicate VFIC codes. **Mitigation**: `transactionCodeRepo.CreateBatch` enforces uniqueness (existing pattern); second export hits duplicate-key error → 409.
- **Risk**: Excel template format drift. **Mitigation**: build from scratch via `excelize.NewFile()` rather than depending on the template file; header-name mapping in the Phase 1 parser handles layout variations.
- **Risk**: Large export (500 employees) blocks the request. **Mitigation**: ≤2s budget; if exceeded, move to async asynq task with download-via-asset pattern (like existing bulk-transfer export does for large files).
