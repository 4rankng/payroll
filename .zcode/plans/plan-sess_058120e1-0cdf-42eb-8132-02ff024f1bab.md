# Plan: Month navigation for the `/employee` page

## Goal (user POV)
An employee opens `/employee` and instantly knows *"which month am I viewing?"*, can go ‹ ›, jump to any month, and return to "this month" — and **every** month-dependent card (advance-payment history, attendance history, timesheets) updates together. State lives in the URL (`?month=2026-07`) so reload / Back / Forward all preserve it.

## UX problems identified (from scout)
1. **No visible month control** on the FlexPay employee page — the only month nav (attendance chevrons) is hidden behind an "expand" toggle.
2. **Advance-payment history has no month dimension at all** (hook + backend accept only `page`/`pageSize` → always latest 10 ever).
3. **Month state is local `useState` only** — lost on reload, not in Back/Forward, not shared between cards.
4. `EmployeeAttendanceHistoryCard` owns its own month internally (diverges from any global selector).
5. `EmployeePage` uses a bare `<Select>` dropdown (no prev/next, no jump, no URL sync).

---

## Phase 1 — Shared frontend foundation

### 1a. `src/hooks/useEmployeeMonth.ts` (new)
URL-backed month state. Single source of truth for the whole page.
- Reads `?month=YYYY-MM` via `useSearchParams`; validates format + not-future; **falls back to current month** on invalid/missing.
- Writes back via `setSearchParams(..., { replace: true })` (matches `TimesheetPage` convention).
- Returns: `{ value:'yyyy-MM', date:Date, label:'Tháng 07, 2026' (vi), fromDate, toDate (yyyy-MM-dd), goPrev, goNext, goToday, canGoNext, isCurrentMonth }`.
- `canGoNext = selected < currentMonth` (no future nav — matches `attendanceHistoryMonth.ts`). Floor at ~24 months back. Reuses `attendanceHistoryMonth.ts` helpers.

### 1b. `src/components/employees/EmployeeMonthNavigator.tsx` (new)
Compact, mobile-first control (no "Tất cả" — admin concept). Reuses existing `Popover`/`Calendar`/`vi` locale (same idiom as `TimesheetMonthSelector`).
- Layout: `‹  [📅 Tháng 07, 2026]  ›` — label is a button opening Popover → `<Calendar mode="single" locale={vi}>` for month/year jump.
- `‹` disabled at floor; `›` disabled when `!canGoNext` (future).
- "Tháng này" pill appears only when `!isCurrentMonth` (one-tap return).
- A11y: `aria-label` on chevrons, `title` tooltips, keyboard-operable Popover, ≥44px tap targets.

## Phase 2 — `FlexiblePayEmployeePage` wiring (flexible employees)

- Call `useEmployeeMonth()`; render `<EmployeeMonthNavigator>` at the top of the shell (below header, above cards).
- **`EmployeeAttendanceHistoryCard`**: remove its internal `useState(new Date())` + hidden chevron block (lines ~150-201). Accept new props `fromDate`, `toDate`, `label`. Fetch attendance via existing `useAttendanceHistory({from_date,to_date})` using the **parent's** month. Keep the expand/collapse list toggle.
- **`AdvancePaymentHistoryCard`**: stays presentational. Parent passes month-filtered `history` (fetched in Phase 5). New `monthLabel` prop → empty state reads `Không có yêu cầu ứng lương trong tháng 06/2026.`
- Guard: request form / check-in card / wallet hero are **not** month-scoped (current eligibility) — leave as-is. Only the two history cards follow the month.

## Phase 3 — `EmployeePage` wiring (weekly/monthly employees)
- Replace `<Select>` month dropdown (lines 213-225) with `<EmployeeMonthNavigator>`.
- `monthFilter` state (line 57) → replaced by `useEmployeeMonth().value`; existing `fromDate`/`toDate` derivation (lines 68-80) feeds the already-month-aware timesheet query.
- Wallet hero / stats already derive from timesheets → update automatically.

## Phase 4 — Backend: month filter on advance-payment history (full stack)

Follow the **admin `created_at` convention** exactly (`applyFilters` lines 426-431, inclusive `>=`/`<=`).

- **Interface** `domain/advance_payment_request.go:122`: `GetByEmployee(ctx, employeeID, limit, offset, fromDate, toDate *time.Time)` — two `*time.Time` (nil = no filter = backward-compatible). Positional style matches existing `GetPendingByDateRange(ctx, fromDate, toDate)`.
- **Impl** `infra/persistence/advance_payment_request_repository.go:51-74`: add two `Where` clauses on the **shared** `query` builder (so `.Count` and `.Find` both see them), guarded by `if fromDate != nil` / `if toDate != nil`. Mirrors `applyFilters`.
- **Service** `service.go`: thread `fromDate, toDate *time.Time` through `GetRequestHistoryByUserID` (315) → `GetRequestHistory` (330) → repo (338). Only one caller, low-risk.
- **Handler** `payment_history_handler.go:13`: parse `fromDate`/`toDate` as `2006-01-02` (mirror `list_requests_handler.go:53-64`); pass through. Keep `page`/`pageSize`.

## Phase 5 — Frontend service + hook
- `advancePaymentService.getAdvancePaymentHistory` (`advance-payment.service.ts:85`): accept optional `fromDate?`, `toDate?` (stringified by existing `buildQueryString`).
- `useAdvancePaymentHistory` (`useAdvancePayments.ts:127`): accept `fromDate`/`toDate` in `filters`; include in query key (month switches refetch → no stale data). Preserve PENDING-poll + toast effect.
- `FlexiblePayEmployeePage`: `useAdvancePaymentHistory({ page:1, pageSize:50, fromDate, toDate })`.

## Phase 6 — States, a11y, polish (spec acceptance)
- **Loading**: each card keeps inline `Skeleton` (employee-page convention); month switch shows per-card skeleton, no full-page flash.
- **Empty**: attendance + advance empty states mention the selected month explicitly.
- **Error**: existing `SectionErrorBoundary` already covers it.
- **Stale-data guard**: query keys include `fromDate`/`toDate` → no cross-month bleed.
- **Desktop/mobile**: single compact navigator row, no horizontal overflow, no hover dependence.

## Phase 7 — Tests & validation
- **Backend**: new repo integration test `TestGetByEmployee_DateRange` in `advance_payment_request_repository_test.go` (seeds 2 months of requests, asserts filter). `cd backend && go test ./... -race -cover`. Then `make api-test`.
- **Frontend**: `cd frontend && pnpm lint && pnpm type-check`.
- Manual: prev/next/jump/today, reload preserves `?month=`, Back/Forward restore, future blocked, empty month shows message.
